# Library action menus and delete confirmation

Card and table actions use `LibraryActionMenu.vue` and one `libraryActions.ts` configuration. The table retains its final **Действия** column. Known unavailable files and recorded torrent dependencies visibly disable media operations with explanations; subtitle/history and identity dialogs remain available. These are UI hints, not proof of eligibility or replacement authorization: every existing server-side gate still applies.

The menu is portalled outside clipping containers and positioned from the corresponding button's current viewport rectangle. It prefers bottom-end with an 8 px gap, flips above when needed, constrains its size/position to the viewport and updates on nested scroll, resizing and observed layout-size changes. Scrolling a trigger outside its clipping container closes its menu. Outside pointer interaction, Escape, Tab and action selection close it; keyboard navigation and focus restoration are supported. Opening a menu does not reset filters, pagination or selection.

Delete opens **Потвърждение за изтриване**, with media title/path, consequences, acknowledgement, **Отказ** and **Потвърди изтриването**. Initial selection makes no API request. The existing explicit analysis builds a server-side exact plan; approval remains disabled until that plan is ready, contains eligible files and is acknowledged. A synchronous in-flight guard prevents repeated approvals, and an accepted approval cannot be resubmitted from that dialog. In-flight approval temporarily prevents dismissal so its server response remains visible. Dismissal never invokes approval. Stale analysis/status responses cannot revive a dismissed dialog.

The existing plan revision/hash, CSRF, idempotency key, authentication, audit, dependency checks and Worker write gates remain unchanged. The UI distinguishes server-accepted approval from server-confirmed completion/failure and displays per-file outcomes. It introduces no endpoint, deletion capability, permission activation or change to metadata/media/torrents.

Regression coverage: `frontend/tests/library.test.ts` covers shared action eligibility, selection/page/filter retention, dismissal, acknowledgement, exact plan payload, concurrent submission and server rejection. `frontend/e2e/library-actions.spec.ts` verifies actual Chromium geometry at desktop/mobile widths, table scrolling, window scrolling/resizing, flip/clamp, keyboard/outside dismissal and single confirmed approval using intercepted synthetic responses. Existing `workspace.spec.ts` continues exercising the real synthetic backend plan flow. CI includes the full backend safety suite, source/dependency/secret checks and both container scans. Browser screenshots are attached in CI artifacts. No merge or deployment is performed by this fix.
